# 场景搭建指南 — 详细实操版

> 适用环境：Unity 2022 LTS，Windows 平台。全部使用空物体 + 组件，零美术资源。

---

## 第〇章：准备工作

### 0.1 确认 Unity 版本

打开 Unity Hub，确认项目使用的版本为 `2022.3.x`（顶部菜单 `Help → About Unity` 可查看）。如果版本低于 2022.3，部分 UI 面板路径可能不同，但核心操作一致。

### 0.2 确认 Text 组件

本指南的 UI 搭建需要 `Text` 组件。Unity 2022.3 默认提供两种：

- **TextMeshPro (TMP)**：更清晰，但首次使用会弹窗要求 "Import TMP Essentials"（点击 Import 即可）
- **Legacy Text**：无需额外导入，直接可用

**建议**：第一次创建 UI → Text 时，如果弹出 TMP 导入窗口，点击 `Import TMP Essentials` 等待导入完成（约 3 秒）。如果不想使用 TMP，在创建时右键 Canvas → `UI` → `Legacy` → `Text` 即可使用旧版 Text。

### 0.3 项目窗口布局建议

将 Unity 编辑器布局设为 `2 by 3`（顶部菜单 Window → Layouts → 2 by 3），这样你会看到：

- **Hierarchy**（左）：场景中的物体列表
- **Scene**（中间上）：3D / 2D 游戏世界视图
- **Game**（中间下）：运行时的游戏画面
- **Inspector**（右）：选中物体的属性和组件
- **Project**（底部）：项目文件目录
- **Console**（底部，与 Project 同标签页）：日志输出

> 如果没有 Console 标签页，点击顶部菜单 `Window → General → Console` 打开。

## 第一章：设置物理层（Layer）

### 1.1 打开设置面板

点击顶部菜单：

```
Edit → Project Settings → Tags and Layers
```

你会在 Inspector 区域看到一个 `Tags & Layers` 面板，分为两部分：

- 上半部分：`Tags`（标签列表）
- 下半部分：`Layers`（层列表，从 Built-in Layer 0 到 User Layer 31）

### 1.2 添加 5 个自定义 Layer

在 `Layers` 区域，滚动到 `User Layer 6` 开始的位置。逐行填入以下名称——

> **操作方式**：点击对应空白输入框，直接输入英文名称，输入后自动保存。

| 位置 | 输入内容 | 用途 |
|------|---------|------|
| User Layer **6** | `Player` | 玩家的物理层 |
| User Layer **7** | `Ground` | 地面物理层 |
| User Layer **8** | `Obstacle` | 障碍物物理层 |
| User Layer **9** | `Coin` | 金币交互层 |
   | User Layer **10** | `Enemy` | 敌人交互层 |
   | User Layer **11** | `Rope`  | 绳索交互层 |
   | User Layer **12** | `Projectile` | 技能弹体层 |

> **为什么从 6 开始？** — Unity 的 Layer 0~5 是内置保留层（Default、TransparentFX、Ignore Raycast、Water、UI 等），自定义 Layer 只能从第 6 个开始。

填完后效果（文字示意）：

```
Layers
  Built-in Layer 0   Default
  Built-in Layer 1   TransparentFX
  Built-in Layer 2   Ignore Raycast
  Built-in Layer 3
  Built-in Layer 4   Water
  Built-in Layer 5   UI
  User Layer 6       Player       ← 你刚填的
  User Layer 7       Ground       ←
  User Layer 8       Obstacle     ←
  User Layer 9       Coin         ←
   User Layer 10      Enemy        ←
   User Layer 11      Rope         ← 新增
   User Layer 12      Projectile   ← 新增（技能弹体）
   User Layer 13
   ...（以下留空）
```

### 1.3 添加 2 个 Tag

在 `Tags` 区域底部点击 **`+`** 按钮，会出现一个 `New Tag` 输入框。输入 `Player`，按回车。**再点一次 `+`**，输入 `Coin`。

> **Tags 用在哪？** — `Player` Tag 挂在 Player 物体上，供 BatController、Obstacle、Coin 等脚本通过 `CompareTag("Player")` 识别。`Coin` Tag 供 Coin 物体自身标记使用。

填完后效果：

```
Tags
  Untagged
  Respawn
  Finish
  EditorOnly
  MainCamera
  Player        ← 新增
  Coin          ← 新增
```

## 第二章：设置 Physics2D 碰撞矩阵

### 2.1 什么是碰撞矩阵？

碰撞矩阵是一张二维表，行和列都是 Layer，**交叉勾选 = 这两个 Layer 的物体之间会发生碰撞交互**。不勾选 = 互相穿透，无任何碰撞回调。

> **关键概念**：两个物体是否交互由两个因素共同决定：
> 1. **碰撞矩阵**：决定 Layer 间的交互开关（总闸）
> 2. **Collider 的 Is Trigger**：决定交互方式——不勾选是物理碰撞（会互相弹开），勾选是触发器（穿透但触发回调）

### 2.2 打开 Physics2D 面板

点击顶部菜单：

```
Edit → Project Settings → Physics 2D
```

在 Inspector 中看到 `Physics2D` 面板。滚动到 `Layer Collision Matrix` 区域。

### 2.3 碰撞矩阵 — 操作详解

这个矩阵的排列是：**行和列都有 Layer 名称，勾选交叉位置即启用交互**。由于 Layer 很多（0~31），表格很长，你需要找到你刚添加的那几行（Player 在第 6 行、Ground 在第 7 行、Obstacle 在第 8 行、Coin 在第 9 行、Enemy 在第 10 行）。

**逐行逐列操作：**

#### 第 6 行（Player）

在 Player 这一行，向右滚动，找到以下列并勾选：

| 交叉列 | 操作 | 原因 |
|--------|------|------|
| Player × **Ground**（第 7 列） | ✅ 勾选 | Player 需要站在地面上，需要物理支撑 |
| Player × **Obstacle**（第 8 列） | ✅ 勾选 | Player 撞到障碍物会被阻挡 + 触发伤害 |
| Player × **Coin**（第 9 列） | ✅ 勾选 | Player 需要检测到金币触发器的进入事件 |
| Player × **Enemy**（第 10 列） | ✅ 勾选 | Player 需要检测到蝙蝠触发器的进入事件 |
| Player × **Rope**（第 11 列） | ✅ 勾选 | Player 可站在绳索上 + 进入绳索触发区域 |
| Player × **Default** 等其他 Layer | ❌ 全部不勾 | 避免干扰与无关节点的碰撞 |

#### 第 7 行（Ground）

Ground 只需要和 Player 交互：

| 交叉列 | 操作 |
|--------|------|
| Ground × **Player** | ✅ （与上面交叉对称，已勾） |
| 其他全部 | ❌ 不勾 |

#### 第 8 行（Obstacle）

| 交叉列 | 操作 |
|--------|------|
| Obstacle × **Player** | ✅（与上面交叉对称，已勾） |
| 其他全部 | ❌ 不勾 |

#### 第 9 行（Coin）

| 交叉列 | 操作 |
|--------|------|
| Coin × **Player** | ✅ （与上面交叉对称，已勾） |
| 其他全部 | ❌ 不勾 |

#### 第 10 行（Enemy）

| 交叉列 | 操作 |
|--------|------|
| Enemy × **Player** | ✅ （与上面交叉对称，已勾） |
| 其他全部 | ❌ 不勾 |

#### 第 11 行（Rope）

| 交叉列 | 操作 |
|--------|------|
| Rope × **Player** | ✅ 勾选 |
| 其他全部 | ❌ 不勾 |

#### 第 12 行（Projectile）

| 交叉列 | 操作 |
|--------|------|
| Projectile × **Obstacle** | ✅ 勾选 |
| Projectile × **Enemy** | ✅ 勾选 |
| Projectile × Player/Ground/Coin/Rope 等 | ❌ 不勾 |

> **最终仅勾选了 7 个交叉项**：Player↔Ground、Player↔Obstacle、Player↔Coin、Player↔Enemy、Player↔Rope、Projectile↔Obstacle、Projectile↔Enemy。这就是整个游戏的所有物理交互关系。

### 2.4 为什么 Coin 和 Enemy 还需要 Is Trigger？

碰撞矩阵只是 "允许交互的总开关"。但具体交互方式由 Collider 上的 `Is Trigger` 决定：

- **Ground / Obstacle + Player**：Is Trigger = **否** → 物理碰撞，Player 站在地面、被障碍物阻挡
- **Coin / Enemy + Player**：Is Trigger = **是** → 穿透但触发 `OnTriggerEnter2D`，用于拾取和受伤判定

> 通俗理解：矩阵是 "电路开关"（通电才有反应），Is Trigger 是 "反应类型"（实体碰撞 vs 穿透触发）。**两者都要配置正确。**

## 第三章：场景 GameObject 逐个搭建

现在正式开始在 Hierarchy 中创建物体。建议按顺序执行，避免遗漏。

### 3.1 创建 Managers 物体

#### 3.1.1 创建空物体

1. 在 **Hierarchy** 窗口空白处 **右键**
2. 弹出菜单 → `Create Empty`
3. Hierarchy 中出现新物体，名称高亮，直接输入 `Managers` 然后回车
4. 确认 Inspector 中 **Position = (0, 0, 0)**（创建出来默认就是这个值）

#### 3.1.2 添加脚本

选中 `Managers` 物体，在 Inspector 底部点击 **`Add Component`** 按钮。在搜索框输入脚本名，双击选中。**依次**添加以下 6 个脚本（顺序无所谓）：

| 序号 | 脚本名 | 作用 |
|------|--------|------|
| 1 | `GameManager` | 管理游戏状态，GameOver 时触发场景重置 |
| 2 | `InputManager` | 每帧检测键盘输入，提供公共标志位 |
| 3 | `UIManager` | 更新分数和血量 UI，控制 GameOver 面板显隐 |
| 4 | `LevelSpeedController` | 提供当前自动移动速度 |
| 5 | `FeedbackManager` | 预留反馈系统（当前为 Debug.Log） |
| 6 | `AudioManager` | 预留音频系统（当前为 Debug.Log） |

#### 3.1.3 Inspector 效果检查

添加完毕后，选中 `Managers`，Inspector 应该显示：

### 3.2 创建地面（Ground）

#### 3.2.1 创建空物体

1. Hierarchy 空白处右键 → `Create Empty`
2. 命名为 `Ground`

#### 3.2.2 设置 Layer

1. 选中 `Ground` 物体
2. 在 Inspector 顶部，点击 `Layer` 下拉框（默认显示 `Default`）
3. 在下拉列表中选择 `Ground`

#### 3.2.3 添加 BoxCollider2D

1. Inspector 底部点击 `Add Component`
2. 搜索 `Box Collider 2D`（注意选带 "2D" 的，不要选不带 2D 的 3D 版本）
3. 双击添加

在 BoxCollider2D 组件中设置：

| 属性 | 设置值 | 操作方法 |
|------|--------|---------|
| **Size** | X=`50`, Y=`1` | 点击输入框直接输入数字，或拖动输入框前的标签来微调 |
| **Is Trigger** | **不勾选** | 保持默认的未勾选状态 |

> **Size.x=50 意味着什么？** — 这是一条 50 米长的地面。当 Player 以 8 米/秒的速度移动时，约 6 秒可以从头跑到尾。如果想让关卡更长，可以增大 X 值或复制多段拼接。

#### 3.2.4 设置 Position

在 Inspector 的 Transform 组件中设置 Position：

```
Position  X 0   Y -3   Z 0
```

> **Y=-3 的含义**：让地面位于画面中下部。Player 起点在 (0,0)，地面在 (0,-3)，Player 会因重力落到地面，Collider 接触后站立。

#### 3.2.5 （可选）拼接多段地面

如果觉得 50 米不够长：

1. 选中 `Ground`，按 `Ctrl + D` 复制
2. 将副本的 Position X 设为 `50`（正好接在第一段末尾）
3. 再复制一段，X 设为 `100`，以此类推

### 3.3 创建 Player（核心步骤，务必仔细）

这是整个搭建过程中最关键、参数最多的物体。**请逐项核对，一步不落。**

#### 3.3.1 创建 Player 根物体

1. Hierarchy 空白处右键 → `Create Empty`
2. 命名为 `Player`

#### 3.3.2 设置 Tag 和 Layer

在 Inspector 最顶部：

1. 点击 `Tag` 下拉框 → 选择 `Player`（这就是你第一章添加的 Tag）
2. 点击 `Layer` 下拉框 → 选择 `Player`（这就是你第一章添加的 Layer）

> **Tag 和 Layer 的区别**：Tag 用于脚本 `CompareTag("Player")` 字符串匹配，Layer 用于碰撞矩阵和 `LayerMask` 物理过滤。一个物体可以有多个 Layer（只能一个）但有多种方式被识别。

#### 3.3.3 设置 Transform

```
Position  X -8   Y 0   Z 0
Rotation  X 0   Y 0   Z 0
Scale     X 1   Y 1   Z 1
```

> **X=-8** → Player 从画面左侧起步，给前面留足够空间。**Y=0** → Player 初始在空中，会因重力落到地面（Y≈-2 位置接触地面）。

#### 3.3.4 添加 Rigidbody2D

1. 选中 `Player` → Inspector → `Add Component`
2. 搜索 `Rigidbody 2D` → 双击添加

在 Rigidbody2D 组件中，从上往下逐项设置：

| 属性 | 设置值 | 为什么这么设 |
|------|--------|-------------|
| **Body Type** | **Dynamic** | Player 需要受重力影响，由物理引擎驱动 |
| **Material** | （留空） | 无需摩擦材质 |
| **Simulated** | ☑ 勾选 | 默认启用物理模拟 |
| **Use Auto Mass** | ☐ 不勾 | 质量由下方 Mass 字段控制 |
| **Mass** | 1（默认） | 对 2D 平台跳跃影响不大，保持默认 |
| **Linear Drag** | 0（默认） | 水平移动由代码直接设置 velocity，不需要阻力 |
| **Angular Drag** | 0.05（默认） | 旋转阻力，实际被 Freeze Z 禁用，无所谓 |
| **Gravity Scale** | **3** | 比默认值(1)重 3 倍，下落更快，跳跃手感更干脆 |
| **Interpolate** | **Interpolate** | 减少 Rigidbody 在帧间的抖动，画面更平滑 |
| **Collision Detection** | **Continuous** | 高速移动时不会被薄障碍物穿透（Discrete 模式可能漏过） |
| **Sleeping Mode** | Start Awake（默认）| Player 一直在运动，不需要休眠省性能 |
| **Constraints** | 展开 → 勾选 **Freeze Rotation Z** | 防止 Player 撞到障碍物后旋转倒地 |

> **Freeze Rotation Z 的作用**：勾选后，无论碰撞还是受力，Player 的 Z 轴旋转永远为 0，始终直立。这是 2D 平台游戏的标准做法。

#### 3.3.5 添加 BoxCollider2D

如果创建 Player 时还没有 BoxCollider2D：
1. `Add Component` → 搜索 `Box Collider 2D` → 添加

设置参数：

| 属性 | 设置值 | 说明 |
|------|--------|------|
| **Is Trigger** | **不勾选** | Player 需要和 Ground / Obstacle 发生物理碰撞 |
| **Material** | （留空） | |
| **Used By Effector** | ☐ 不勾 | Base On 等等保持默认 |
| **Edge Radius** | 0（默认） | 2D Collider 边缘圆角，0 就是直角 |
| **Size** | X=`0.8` , Y=`1.8` | 宽 0.8 米、高 1.8 米，模拟人体躯干 |
| **Offset** | X=`0` , Y=`0` | Collider 相对于物体原点的偏移，保持居中 |

> **Size.x=0.8 意味着什么？** — Player 可以穿过小于 0.8 米的缝隙。地面上的尖刺（Size 0.6）比 Player 窄，但靠得近仍会触发碰撞。

#### 3.3.6 添加 PlayerController 脚本

1. `Add Component` → 搜索 `PlayerController` → 添加

添加后 Inspector 中展开 PlayerController，你会看到 5 个分组：

##### 分组 1：「移动」

| 参数 | 默认值 | 说明 |
|------|--------|------|
| **Fallback Speed** | 8 | 当找不到 LevelSpeedController 时的备用速度。正常运行时会被覆盖为 LevelSpeedController 的 CurrentSpeed |

##### 分组 2：「跳跃」

| 参数 | 默认值 | 影响 |
|------|--------|------|
| **Jump Force** | 12 | 跳跃瞬间赋予的 Y 轴初速度。越大跳得越高。>15 可能跳出屏幕 |
| **Gravity Scale** | 3 | 重力倍率（已由 Rigidbody2D 设置，此处仅为引用，实际效果由 Rigidbody 控制） |
| **Coyote Time** | 0.1 | 离开平台边缘后 0.1 秒内仍可跳跃。解决 "明明按了却跳不起来" 的问题 |
| **Jump Buffer Time** | 0.1 | 落地前 0.1 秒按下跳跃，落地后自动执行。解决 "落地瞬间按晚了" 的问题 |
| **Max Jumps** | 2 | 最大跳跃次数。2=二段跳，1=只能单跳 |
| **Ground Layer** | None | **必须设置！** 点击下拉 → 只勾选 `Ground` |

> **Ground Layer 必须设置**：如果此处为空，地面检测永远找不到地面，跳跃功能完全失效。

##### 分组 3：「地面检测」

| 参数 | 默认值 | 说明 |
|------|--------|------|
| **Ground Check Distance** | 0.1 | 地面检测框在 Collider 底部下方延伸 0.1 米。增大可提高识别范围 |
| **Ground Check Width Ratio** | 0.8 | 检测框宽度为 Collider 的 80%。0.8=略窄于 Collider，减少边缘误判 |

> 这两个参数通常不需要调整，除非遇到地面检测不稳定（Player 明明站在地面上却 `isGrounded=false`）。

##### 分组 4：「滑铲」

| 参数 | 默认值 | 影响 |
|------|--------|------|
| **Slide Collider Height** | 0.9 | 滑铲时 Collider 高度从 1.8 变为 0.9（一半） |
| **Stand Collider Height** | 1.8 | 站立时 Collider 高度，应与 BoxCollider2D 的 Size.y 一致 |
| **Slide Cooldown** | 0.1 | 松开 S 键 0.1 秒后才能再次滑铲 |

##### 分组 5：「攻击」

| 参数 | 默认值 | 影响 |
|------|--------|------|
| **Attack Range** | 1.5 | 攻击框在 Player 右前方延伸 1.5 米 |
| **Attack Height** | 1.2 | 攻击框高度 1.2 米（上下各 0.6 米） |
| **Attack Duration** | 0.2 | 攻击框持续 0.2 秒（实际只检测按下的瞬间） |
| **Attack Cooldown** | 0.15 | 攻击后摇 0.15 秒内无法再次攻击 |
| **Enemy Layer** | None | **必须设置！** 点击下拉 → 只勾选 `Enemy` |

> **Enemy Layer 必须设置**：如果此处为空，攻击判定找不到任何敌人，攻击完全无效。

##### 分组 6：「生命值」

| 参数 | 默认值 | 说明 |
|------|--------|------|
| **Max Health** | 100 | 总血量 |
| **Current Health** | 100 | 当前血量（运行时自动变化，初始为 maxHealth） |

#### 3.3.7 添加 MountSystem 和 EnergySkillSystem

选中 `Player`，依次点击 `Add Component` 添加：

- `MountSystem` — 无需任何配置，仅占位
- `EnergySkillSystem` — 无需任何配置，默认值已可用

添加后 Inspector 中会出现这两个脚本的折叠面板，保留默认值即可。

- [ ] BoxCollider2D → Size=(0.8, 1.8)，Is Trigger = 否

### 3.5 创建 Coin（金币）预制体

## 第七章：手动摆放关卡物体

### 7.1 创建关卡容器

### 7.2 摆放金币

1. 在 Project 窗口的 `Assets/Prefabs/` 中，选中 `Coin` 预制体
2. **拖入** Hierarchy 中的 `LevelObjects` 下面
3. 设置该 Coin 实例的 Position，例如：

```
Position  X 2   Y -1   Z 0   ← 离地面 2 米高（地面 Y=-3，Coin Y=-1）
```

4. 选中这个 Coin，按 `Ctrl + D` 复制多个，逐个调整 X：
   - Coin 1：X=2
   - Coin 2：X=4.5
   - Coin 3：X=7
   - Coin 4：X=9.5
   - ...

> **复制快捷键**：Ctrl+D 会在原地复制一个完全相同的物体，你只需要修改 Position 值即可。

### 7.3 摆放障碍物

从 `Assets/Prefabs/` 拖入 `Obstacle_Spike` 或 `Obstacle_Crate` 到 `LevelObjects` 下：

- 尖刺 (Spike)：Position Y ≈ -2.2（正好站在地面上，因为地面顶面 Y=-2.5）

实际上地面位置是 Y=-3，地面 BoxCollider Size.y=1，地面顶面 = -3 + 0.5 = **Y=-2.5**。障碍物应该放在这个高度。

> **精确计算**：障碍物 Position Y = 地面顶面 Y + 障碍物 Collider Size.y/2 = -2.5 + 0.4 = **-2.1**（尖刺）或 -2.5 + 0.5 = **-2.0**（木箱）。你也可以直接拖到 Scene 视图手动对齐。

摆放参考：

| 物体 | X 坐标（示例） | Y 坐标 | 间距 |
|------|---------------|--------|------|
| Obstacle_Spike | 6 | -2.1 | — |
| Obstacle_Crate | 12 | -2.0 | 距上个障碍物 6 米 |
| Obstacle_Spike | 18 | -2.1 | 距上个障碍物 6 米 |
| Obstacle_Crate | 25 | -2.0 | 距上个障碍物 7 米 |

### 7.4 摆放蝙蝠

从 `Assets/Prefabs/` 拖入 `Bat` 预制体到 `LevelObjects` 下。

蝙蝠应该放在空中，营造高低差挑战：

| Bat | Position | 巡逻方向 |
|-----|----------|---------|
| Bat 1 | (10, 1, 0) | 水平，在金币线之上 |
| Bat 2 | (16, 0.5, 0) | 水平，需要跳跃攻击 |
| Bat 3 | (22, 2, 0) | 水平，高处 |

> **蝙蝠巡逻范围**：默认 `patrolRange=4`，从出生点向左和右各飞 4 米。摆放在 X 坐标时，蝙蝠会在 X-4 到 X+4 范围内往返。确保巡逻范围内有足够的空间。

### 7.5 摆放绳索

从 `Assets/Prefabs/` 拖入 `Rope` 预制体到 `LevelObjects` 下。

| Rope | Position | 说明 |

### 8.4 常见问题深度排查

#### 问题：Player 不移动

| 检查点 | 操作 |
|--------|------|
| ① | 选中 Hierarchy 中的 `Managers` 物体，Inspector 中是否有 `Level Speed Controller` 脚本？ |
| ② | 如果已挂载，查看其 `Fixed Speed` 是否大于 0？ |
| ③ | 查看 Console 是否有红色错误。如果报 "LevelSpeedController does not contain a definition for 'Instance'"，说明脚本没有单例方法，请重新导入 LevelSpeedController.cs |

#### 问题：跳跃完全无效

| 检查点 | 操作 |
|--------|------|
| ① | 选中 Player，查看 PlayerController → `Ground Layer` 下拉 → 是否只勾选了 `Ground` 层（没有勾其他层）？ |
| ② | Ground 物体的 Layer 是否设为 `Ground`？ |

#### 问题：金币碰到了但没有任何反应

| 检查点 | 操作 |
|--------|------|
| ① | Coin 预制体的 CircleCollider2D → `Is Trigger` 是否勾选？ |
| ② | Coin 物体的 Tag 是否设为了 `Coin`？ |
| ③ | 碰撞矩阵中 Player×Coin 是否勾选？ |

#### 问题：障碍物直接穿过去了

| 检查点 | 操作 |
|--------|------|
| ① | Obstacle 预制体的 BoxCollider2D → `Is Trigger` 是否**不勾选**？ |
| ② | 碰撞矩阵中 Player×Obstacle 是否勾选？ |

#### 问题：蝙蝠完全不移动

| 检查点 | 操作 |
|--------|------|
| ① | Bat 预制体的 Rigidbody2D → `Body Type` 是否设为 `Kinematic`？（不是 Dynamic） |
| ② | BatController 的 `Move Speed` 是否大于 0？ |

#### 问题：按 J 攻击无效（绿色框显示了但打不到蝙蝠）

| 检查点 | 操作 |
|--------|------|
| ① | PlayerController → `Enemy Layer` 下拉 → 是否只勾选了 `Enemy`？ |
| ② | Bat 物体的 `Layer` 是否设为 `Enemy`？ |
| ③ | 蝙蝠是否在攻击框范围内？在 Scene 视图中选中 Player，观察绿色线框位置，确认蝙蝠在框内 |

#### 问题：GameOver 面板不显示，或分数/血量不刷新

| 检查点 | 操作 |
|--------|------|
| ① | 回到第五章，确认 UIManager 的三个字段都已绑定正确的物体 |
| ② | 确认 GameOverPanel 是**子物体**没有被其他物体遮挡（检查 Hierarchy 位置） |
